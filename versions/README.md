# TextMap 推断版本

新 `prepare()` 接口的历史范围、快照身份和依赖持久化见 [缓存接口](../docs/cache-provider.md)。它按显式 historyRefs 拼接固定提交的 first-parent 序列；本地实际源仓库需要 master 与 HEAD 两段，单独 HEAD 仅有 7 个快照。下文旧命令仍保留原有 `--all` 历史模式；经过模式、语言、源目录和完整前缀验证后，可将旧 SQLite 状态只读迁移到新缓存。对象哈希依赖现额外保存为内部 `dependencies/<folder>.json`，不进入网站展示字段。

`npm start` 在导出前自动构建历史索引；`npm run buildversions` 只构建索引。
`npm run exportversions` 仅根据简体中文和英文重新计算并导出对象版本表，不改动现有正文、图片、数值曲线或 InterAction 文件；此模式依赖现有 `export/EN` 数据（故事、语音、秘境补充需要它）。常规 `npm start` 仍导出全部 15 种语言的正文，但版本推断只使用 CHS/EN；各语言查询共用同一版本表。
要求 Node.js 22.13+（内置 SQLite）及非浅克隆的源数据 Git 仓库。

规则：

1. 版本推断只考虑简体中文 CHS 和英文 EN，固定顺序为 CHS、EN。
2. 每个哈希的简体中文和英文原文组成内容身份；统计每个历史快照中拥有相同内容的哈希数量。单个哈希只计一次，而不是按语言文件出现次数计数。其他语言的新增、修改、删除均不参与统计；仅存在于其他语言的哈希不进入索引。
3. 内容数量最后发生变化的快照版本，是当前拥有该内容的所有哈希的“可能出现版本”。增减均算变化；同内容更换哈希但总数不变，不更新版本。
4. 记录对象在简体中文和英文提取时实际读取的 TextMap 哈希，包括嵌套字段、文件名查询及复制的角色名称。取这些哈希的最早可能版本作为对象版本；两个语言的对象依赖合并取最早值，其他输出语言不参与版本聚合。
5. `<=1.4` 写成 `1.x`。没有 TextMap 依赖的对象写空字符串，不猜测版本。

输出为两个目标目录中的 `version/<folder>.json`，键是对象文件名，值是版本字符串，直接兼容 genshin-db 已有版本读取逻辑。正常导出替换该分类版本表；秘境怪物列表二次补充合并取最早值。
InterAction 原样复制文件没有经过 TextMap 翻译，不在这些分类版本表中；音频文件和数值曲线也不推断版本。

支持历史 TextCHS/TextEN 和现代 TextMapCHS/TextMapEN；同语言存在现代文件时不使用旧命名文件；Medium 和分片覆盖顺序与当前导出一致。比较使用原文，不应用任何文本清洗。内部使用每种参与语言的 128 位 SHA-256 指纹减少存储，保留两个固定语言槽位；缺失语言不同于空字符串。后来增加意大利语、土耳其语等语言不再影响内容身份或数量。指纹存在理论碰撞概率。

旧命令的缓存默认位于操作系统用户缓存 `Inteyvat-Wiki/genshin-data/history/textmap-versions-chs-en/`，可通过 `GENSHIN_DATA_CACHE` 改变根目录：包含 SQLite 历史状态、当前哈希版本表 `hashes.json` 和 `manifest.json`。新 prepare 接口使用同一缓存根的 `history/<内容身份>/`。不再自动读取或写入包内 `.cache`，原有本地缓存不移动、不删除；需要迁移时显式传入 `historySeedCache`。缓存身份和指纹包含参与语言及模式版本。首次回溯开销较大，之后支持按提交增量更新和中断续跑。参与推断的 CHS/EN TextMap 未提交修改会报错，避免给未知快照标注版本。缓存不提交到 Git。

旧命令需通过 `GENSHIN_DATA_CONFIG` 显式选择 JSON 配置，再用 `textmap_version_cache` 更改历史缓存目录，用 `textmap_version_overrides`（完整提交 SHA 到 `major.minor` 的映射）修正源提交版本标注；不会自动读取仓库的 `config.json`。新接口使用 `cacheRoot`、`versionOverrides`、`historyRefs`、`historySeedCache`。配置覆盖优先于程序内置特判，内置特判优先于提交标题。改变已处理历史的版本或顺序时须换用新缓存目录。无版本号的提交继承前一快照版本；同一版本的多次提交按历史顺序处理。

这是文本数量启发式推断，不是真实上线日期。翻译修订、重复文本增删、源仓库缺失快照，以及错误的提交版本号都会影响结果。当前历史始于 1.4，只能把更早内容归到 `1.x`。

已核实的历史特判：`1a6597f5a67382119494beae22a4039a1cefc8e1` 的提交标题标注 3.0，但相较前一个 3.2 快照新增了「倾落伽蓝」章节（ID 1307、标题哈希 2100565426），并新增意大利语和土耳其语 TextMap，应按 3.3 处理。程序以完整 SHA 精确匹配这一提交，不影响正常的 3.0 提交，也不更改源仓库 Git 历史。未核实的版本回退仍会警告。

验证：`npm run test:versions`。
